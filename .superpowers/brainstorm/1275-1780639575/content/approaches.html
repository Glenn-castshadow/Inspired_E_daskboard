Three approaches to material tracking

All three use the same iPhone QR → mobile web flow. The difference is scope and what gets added to the existing codebase.

A

Core only ⭐ Recommended

Extend the existing inventory system with label support. No new tab, no audit history. Just the essential scan-in / scan-out loop and the Fulfillment badge.

WHAT GETS ADDED
DB label_pool table — pre-generated label IDs (unassigned / assigned)
label_id column on inventory_items
category_blank_sizes — category → default W×H
Rust 3 new routes on inventory HTTP server:
GET /m/:id — scan landing page
POST /m/:id/in — check in (assign + dimensions)
POST /m/:id/out — check out (mark used)
UI Label pool section in Inventory tab
QR batch print view (opens in browser)
Offcut badge in Fulfillment tab rows
  • Smallest blast radius
  • Reuses all existing infrastructure
  • Shippable in one session
  • No check-in/out history
  • Label pool managed from desktop only
B

Core + transaction log

Everything in A, plus a lightweight history of every check-in and check-out event. Useful for knowing when material was last moved and spotting losses.

ADDS ON TOP OF A
DB material_events table — label_id, event (in/out/create), timestamp, notes
UI "Last moved: 3 days ago" shown on inventory rows
Expandable history per item
  • Answers "where did that piece go?"
  • Low extra complexity
  • More DB writes on every scan
  • Slightly more to build
C

Core + log + Materials tab

Everything in B, plus a dedicated Materials tab in the dashboard — label pool management, offcut browser with fit-check query, full history view.

ADDS ON TOP OF B
UI New "Materials" tab — label pool table (generate / print / revoke),
offcut browser with "find pieces that fit W×H" query,
transaction history table
Scope ~2× the frontend work of A. New Rust module (material.rs) cleaner than extending inventory.rs further.
  • Most complete UX
  • Clean module separation
  • Ad-hoc offcut lookup built in
  • Another tab in an already tabbed app
  • Most work to build
My recommendation: A. You're one operator. You don't need audit history to know where material went — you were there. A new tab adds navigation cost for marginal gain. Get the scanning loop working first; B or C can be layered in if you find you miss the history.
